0. 这份报告要解决什么问题

上一版调研（智人TV生态调研.md）回答的是「名字怎么拼」，结论落在命名学上。 这一版换了个问题：

「谁在拍、谁在传、谁在看、谁在赚」——这条内容供应链的实际结构是什么。

换了问题之后，最重要的发现是上一版漏掉的一层：被拍摄者自己也是创作者。 这直接推翻了「搬运号剥削素人」的简单叙事，也决定了这个库该怎么建。

1. 五条核心发现

1.1 不是四层，是「四层 + 一层合谋」

TV 系通常被理解成「一群搬运号把素人的窘态剪成合集」。 实测结构比这复杂，而且第一层和第二层经常是同一个人：

L0  原始主体        视频里的人          ← 二甩哥爱老婆、甩舅子
L1  自拍原生创作者   自己拍自己发，且自己用这个标签  ← 二甩哥爱老婆（同一人）
L2  搬运号          把 L0/L1 的素材剪成「XXTV」合集  ← 享福TV、虎王酱、搬石娘
L2' 二创号          在搬运上加配音/字幕/鬼畜         ← 飞行社社长
L3  元层            讨论这个现象本身                 ← 知乎答主、介绍号
L4  观众            只在评论区出现                   ← 1060 条评论样本

二甩哥爱老婆是这个结构的活体证据： - 76,685 粉、760 条投稿、单条最高 198 万播放 - 签名：「我是一个来自贵州大山卡卡的，从小喜欢吃坨坨肉……」 - 他自己的标题就写「享福TV，吃酒席了，坨坨肉随便吃了」

也就是说：这个标签原本是别人贴给他的嘲讽，现在成了他自己的品牌前缀。 搬运号「享福TV」（70,894 粉）和他的粉丝量是同一量级。

结论：这不是单向剥削，是一个有交换的结构。 素材流向搬运号，流量回流到主体。代价由谁承担是另一个问题，但「受害者完全被动」这个假设是错的。

1.2 系列名分两种产权：公共命名空间 vs 独占

Kind 特征 实例
公共命名空间 几十个号共用，谁都能起这个名字 智人TV（26 UP / 92 条）、神人TV（26 UP / 42 条）、享福TV（18 UP / 78 条）
独占系列 一个号把名字占了，别人不用 暗黑TV（1 UP / 49 条 / 885 万播放）、星欲TV（1 UP / 26 条）

暗黑TV 是最典型的：49 条视频、885 万播放，全部来自「暗黑制片人」一个号。 这说明「XXTV」不是一个组织，是一个可被抢占的命名位—— 谁先做出量，谁就把这个词变成自己的栏目名。

1.3 账号的自我包装是「学术化」

搬运行为在道德上站不住，所以命名体系发明了一整套头衔来洗白它：

头衔 数量（核心账号中） 作用
研究院 / 研究所 5 把围观说成研究
观察员 / 观察社 4 把偷窥说成田野调查
社长 / 院长 / 洞主 6 自封机构负责人

最典型的一句签名（飞行社社长，84.3 万粉）：

「是一名智人，兼智人观察员。主营业务：社会观察，升智，黑色幽默」

把「看人出丑」写成「社会观察」，是这个生态最核心的修辞操作。

1.4 搜索联想词暴露了「梗的扩散阶段」

B站 搜索框下拉词（不是我们编的，是真实用户在搜）：

联想词 读法

方法价值：联想词是需求侧证据，比搜索结果的标题更接近「观众脑子里这个系列长什么样」。 这一条在上一版调研里完全没有。

1.5 封号是真实存在的，但比想象中隐蔽

库里有 8 个名字含「已注销」的账号，其中一个（10,073 粉）的视频还在被索引：

[智人TV]家越穷，规矩越多这一块 — 425,552 播放

账号没了，视频还在。这正是「备份」这件事的真正必要性： 不是防 UP 删稿（那是少数），是防平台清号（视频跟着一起没）。

1.7 溯源：搬运层系统性隐藏来源

这是做 derivations（二创溯源）时最重要的发现，也是整个生态的结构性事实。

逐条看过核心搬运号的简介，没有一条是来源标注，全是免责声明：

Account 简介原文
搬石娘 「素材来源于网络，如侵联除」
搬石高手北极熊 「AI生成，谨慎甄别，无不良引导，请勿模仿」
蓝白灬绯 「视频内容来源网络 / 仅供娱乐 / 侵权请联系删除」
伪人研究院院长 「B友们帮助点点关注点点赞，爱你哟」

四种自动溯源路径的实测结果：

Method 结果
简介解析 0 条（没有可解析的署名格式）
评论解析 8,904 条里含「原视频/出处/来源」的样本全是误匹配（匹配到「艺术来源于生活」）
@提及 都是观众互相 @，不是署名
related 推荐位 不给原始来源，给的是「同系列的其他搬运号」

「不署名」本身就是结论：搬运层靠模糊来源规避责任。这不是疏忽，是策略。

实际可行的只有两条：related 聚类建系列级关系（已验证 454 条边）； 标题包含度匹配建视频级关系（阈值 0.85，去掉装饰后完全包含记 1.0）。

怎么找到的：related 推荐位，不是搜索

这是这一轮最重要的方法论发现。

用搜索找 L0 是死路。 他们的标题是流水账（「天冷了吃个火锅！」）， 里面没有「TV」，用任何系列名都搜不到。

但 related 推荐位能挖到。 因为 B站 的算法是按内容聚类，不是按命名：

从二甩哥的视频出发 → related →
  两个瘦人 / 雪花阿糕啊 / 搞笑毛哥哥 / 酱总家的山村美味 /
  农村扛把子快餐村 / 张知晨 / 甩妹夫Alp / 甩妹 / 山野木木吉 …

这些号的标题全是流水账，正是 L0 的特征。

这条路的额外好处：related 接口从不被封。 search/type 和 space/arc/search 会 -412 request was banned， 而且是账号级的——我试过用香港 IP 换着打，一样被封（只是错误码从 -412 变成 -799）。 但 related / view / comments 一直可用。所以架构上必须把发现拆成可降级的通道。

没达到 30 个的原因（诚实记录）

目标是 30 个，实际 16 个。原因是：

  1. space/arc/search 账号级封禁——没法批量拉候选号的投稿来验证， 只能靠 related 一条条爬，速度慢一个数量级。
  2. related 的图长得慢——第二轮只新增 3 个 UP，因为大部分候选在库里没有视频， 没法当新种子。
  3. 噪音率高——_looks_original 第一版用了「吃/喝/肉」这类泛食物词， 把美食区、旅游区的大号全带进来了（在日本摸鱼的小超人、李李真会吃、老高吃饱了）。 改成「村/山/穷/赌/酒/三和/日结」这类处境词后才干净。

下一步要突破 30 个：等 space 接口解封（或换一个 B站 账号）， 拉每个候选的投稿列表做标题比对验证。这个流程 tvdb/l0.py --verify 已经写好了。

4.1 三条硬教训

① 搜索会被封，而且封得很突然。 实测连续 35–40 次 search/type 后返回 -412 request was banned，持续 15–30 分钟。 期间 search 和 space 全挂，但 related、view、comments 仍然正常。 所以架构上必须把「发现」拆成可降级的通道，而不是死磕搜索。

② 中文抽梗不能用 n-gram。 实测 1,060 条评论做 2–6 字 n-gram + 停用词 + 稀有字过滤， 排名前列是「希望 / 朋友 / 甚至 / 好像 / 弹幕 / 告诉 / 老师」——全是普通词。 原因：中文没空格，n-gram 会把「视频的」切成「视频」「频的」「的视频」互相稀释； 而真正的梗往往只出现几次，按频率排序天然被埋。 改用 LLM（glm-5.3-flash）后立刻可用，抽出「李文亚」「剑人=贱人」「地球online」 「零帧起手」「跳完舍友能保研」这类真梗。

③ 推荐位是双刃剑。 它能把没写 TV 的原生素材带进来（这是它的价值）， 但也会带进罗翔、影视飓风这种千万级主流号（这是它的噪音）。 所以必须有相关性打分 + is_core 过滤，否则「粉丝前 20」全是无关大号。

5.2 四条设计原则

  1. 可复现：每条数据都记 crawl_id，crawls 表存完整参数。 任何结论都能回溯到「哪一次抓取、用什么参数、抓到了什么」。
  2. 不覆盖，只追加：播放量进 video_stats 时间序列，主表只留首末值。
  3. 软删除：视频被删不是 DELETE，是 alive=0 + disappeared_at。 「消失」本身就是研究数据。
  4. 原始 JSON 必须留：解析规则会变，原始响应不会。

5.3 容量预算

1. 生态结构：四层，不是一层

TV 系常被理解成「一群搬运号」。实测不是。真实的层级是：

层 Role 干什么 和下一层的关系
L0 Original subject 视频里被拍摄的人。可能自己不开号，也可能开号。是素材的源头。 —
L1 Self-filming creator 自己拍自己发，且自己使用了 TV 标签。被观察者内化标签，是这个生态最特殊的现象——他们靠被围观获得收入。 —
L1' Original shooter 拍别人（亲友/同村/顾客），发布原始素材。多数不用 TV 标签。 —
L2 Reposter 不自拍，把别处的素材剪成合集并加 TV 标签。生态的「编辑」层。 —
L2' Derivative editor 在搬运基础上做加工：配音、字幕、鬼畜、reaction、盘点。 —
L2'' Researcher 自称研究/观察/记录，用学术外衣包装围观。命名体系的核心修辞。 —
L3 Commentator 以评论、解读、批判为主，不主要发布素材。 —
L3' Meta-content account 介绍网络热门人物/事件本身的号，观众通过它认识这个生态。 —
L4 Viewer 只在评论区出现，不生产内容。研究态度分布的主要样本。 —

最关键的一条：L0（原始主体）和 L1（自拍原生）经常是同一个人。 这打破了「搬运号剥削素人」的简单叙事——被拍摄者自己也在拍、自己也在用这个标签、 自己也在赚钱。这不是单向的剥削，是一个有交换的结构。
